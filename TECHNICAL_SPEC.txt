## 3. Architecture

### 3.1 Overview
A single-page static site. The browser loads `index.html`, which contains inline CSS and JavaScript. No server-side code runs.

```
Visitor browser --HTTPS--> GitHub Pages (static files)
                              |-- index.html (HTML + CSS + JS)
                              |-- screenshots/*.png
                              |-- scan_results.txt / .xml
                              '-- Google Fonts (optional, falls back to system fonts)
```

### 3.2 Why this design
- One file means nothing can break between files and deployment is a single push.
- No framework means no dependencies to patch and fast load.
- Google Fonts is the only external request; system-font fallbacks keep the page readable if it fails.

### 3.3 Repository layout
```
task1-network-port-scan/
├── index.html
├── README.md
├── TECHNICAL_SPEC.txt
├── scan_results.txt
├── scan_results.xml
└── screenshots/
    ├── 01_ip_a_and_first_scan.png
    ├── 02_syn_scan_subnet.png
    ├── 03_service_scan_part1.png
    └── 04_service_scan_complete.png
```

## 4. Implementation Details

### 4.1 Page sections (in order)
1. Header: sticky nav with anchor links.
2. Hero: headline "I scanned 256 addresses. Three answered.", summary, metadata, two buttons, and an animated terminal replaying the real scan output.
3. Objective and tools.
4. Lab environment table.
5. Method: numbered steps (a true sequence) with exact commands.
6. Results: interactive subnet map, scans table, hosts/ports table, screenshots, raw-file links.
7. Services and risks: risk table, assessment, hardening.
8. What I learned: skill chips and takeaways.
9. Interview questions: native `<details>` accordion.
10. Repository structure and next steps.
11. Footer: contact links and ethics note.

### 4.2 Interactive subnet map
- JavaScript builds 256 cells (16 x 16), one per address in `10.0.2.0/24`.
- Cells 2, 3 and 15 are `<button>` elements; the rest are inert, `aria-hidden` squares.
- Selecting a host sets `aria-pressed` and shows its role, open ports and filtered count in a live region.
- Data lives in the `hosts` object in the script. To add a host, add an entry keyed by the last octet.

### 4.3 Terminal replay
- Lines are in the `L` array and are appended one at a time with `setTimeout`.
- With `prefers-reduced-motion: reduce`, all lines show immediately and the cursor does not blink.
- The terminal has an `aria-label` summarising the output for screen readers.

### 4.4 Screenshot placeholders
Each `<img>` has an `onerror` handler that hides the broken image and reveals a dashed "Add screenshots/..." box, so missing evidence is obvious instead of showing a broken icon. Remove nothing; the box disappears once the file exists.

### 4.5 Design system
| Token | Light | Dark |
|---|---|---|
| Background | #f2f4f7 | #0a111d |
| Surface | #ffffff | #111b2c |
| Text | #101a2b | #e8eef8 |
| Accent | #0b5fd1 | #6aa6ff |
| "Open port" amber | #b4620a | #f2b052 |

- Fonts: Bricolage Grotesque (headings), IBM Plex Sans (body), IBM Plex Mono (commands, terminal).
- The amber colour is used only to mean "open port", so colour carries meaning.
- Theme follows the visitor's OS setting via `prefers-color-scheme`.
- Layout: max width 1040 px, two-column grids collapse to one column below 760 px.

### 4.6 Accessibility
Semantic landmarks, one `h1`, visible focus rings, alt text on screenshots, keyboard-operable map and accordion, reduced-motion support, contrast checked for both themes.

### 4.7 Performance
Target Lighthouse 95+ in all categories. No images on first load except screenshots (add `loading="lazy"` if files are large; keep each PNG under 500 KB).

### 4.8 Security and privacy
- No cookies, trackers or form inputs.
- Do not publish real public IPs, Wi-Fi names, passwords or other people's devices. All data here is a private NAT lab (10.0.2.0/24).
- Scans must only target systems you own or are authorised to test.

## 5. Deployment (free, GitHub Pages)

1. Create a repo named `task1-network-port-scan` (or `<username>.github.io` for a main portfolio URL).
2. Add all files from section 3.3.
3. Commit and push to `main`.
4. In the repo go to Settings > Pages > Source: "Deploy from a branch", Branch: `main`, Folder: `/ (root)`. Save.
5. Wait 1-2 minutes. The site is live at `https://<username>.github.io/task1-network-port-scan/`.
6. Paste the repo link into the internship submission form before the 10:00 PM deadline.

Updating: edit, commit, push. Pages redeploys automatically.
